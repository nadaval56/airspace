# מגבלות מרחב אווירי

אתר סטטי אחד שמציג מפה של המרחב האווירי בישראל ועליה כמה שכבות.

1. **מגבלות קבועות** — אזורים אסורים, מוגבלים ומסוכנים לטיסה, מתוך פמ"ת פרק א-17 (נספחים ב' ו-ג').
2. **מגבלות זמניות** — נוטאמים פעילים של מרחב תל אביב (LLLL), מתעדכנים אוטומטית כל שעה.

נכנסים לאתר ביוזמה, כשרוצים לדעת מה המצב. אין התראות, אין מנוי, אין הרשמה.

---

## אזהרה

> **מידע זה אינו מיועד לשימוש מבצעי. אינו מחליף תדריך רשמי או תיאום מול הגורמים המוסמכים.**

זה לא נוסח משפטי לעיטור. הכלי מסתמך על מקור צד־שלישי לא רשמי, ופעילות מקומית
בגובה נמוך לרוב אינה מופצת בערוץ הנוטאמים הבינלאומי כלל.

**היעדר נוטאם באתר אינו ראיה להיעדר מגבלה.**

## איך זה עובד

```
GitHub Actions (cron, כל שעה)
        ↓
  scripts/fetch_notams.py  — משיכה + פרסור
        ↓
  data/notams.json  ←  commit ל-repo
        ↓
GitHub Pages: index.html קורא JSON סטטי
```

הדף **לא** פונה למקור חיצוני בזמן טעינה — מקורות הנוטאמים חוסמים CORS.
המחיר הוא עיכוב של עד שעה בין פרסום נוטאם להופעתו באתר.

## מקורות הנוטאמים

הסקריפט מושך מכל המקורות ומאחד, כדי שנפילה של אתר אחד לא תרוקן את הדף.
מקור שדורש אישורים ולא הוגדר מדלג על עצמו בהודעה ברורה, ואינו נחשב ככשל.

### המקור הפעיל: רשות שדות התעופה

`brin.iaa.gov.il/aeroinfo` — המקור **הרשמי הישראלי**, והיחיד מכל מה
שנבדק שמחזיר 200 בלי אימות ובלי חסימה. הוא מספק גם נוטאמים וגם METAR
ו-TAF, מאותו דף, לפי `msgType`. אין צורך בשום הרשמה.

הוא גם מפרסם את **סדרה C** — הסדרה הפנים־ארצית — שאינה מופצת בהכרח
בערוץ הבינלאומי. זה בדיוק הפער שהבאנר באתר מזהיר מפניו.

שתי מגבלות שכדאי להכיר:

* **אין שורות Q בדף הרשימה.** להודעה שטרם הורחבה, הגיאומטריה מגיעה
  ממה שאפשר לחלץ מטקסט ההודעה (`PSN 3055N03446E` + רדיוס `NM`).
  הודעה שכבר הורחבה מביאה שורת Q אמיתית, ואיתה גיאומטריה מדויקת.
* **אין זמני תוקף** בדף הרשימה. הם נפתחים בכפתור ה-`+`, וזו בקשה
  נפרדת לכל הודעה — ראו למטה.

#### כפתור ההרחבה: איך הוא עובד, ואיפה נתקעתי

בלחיצה על ה-`+` נפתח הנוטאם המלא — שורת Q, פריטי B)/C)/D), הכול:

```
Q) LLLL/QAELC/IV/NBO/E /000/019/3059N03445E001
A) LLLL B) 2608160800 C) 2608201000
D) 16 0800-1500 1600-2059, 17 0600-0900 1000-1500 1600-2059, ...
```

`MoreInfo.js` מראה שזה **postback רגיל של WebForms**: ארבעה שדות
מוסתרים ואז `btnMoreInfo.click()`. יש בקובץ גם נתיב ישן דרך
`AeroInfo.asmx?op=getMoreMsgInfo`, אבל כל שורה בו מסומנת כהערה.

שתי טעויות שלי בדרך, שתיהן שוות תיעוד:

1. **`msg_num` נקרא מ-`MoreImg_0`** — האינדקס של השורה ב-DataList.
   המספר הנכון הוא מזהה ההודעה, ויושב ב-`divMainInfo_<n>` העוטף:
   ה-`onclick` עושה `.substr(12)` על מזהה האב, ו-`"divMainInfo_"` הוא
   בדיוק 12 תווים. כלומר `2046996`, לא `0`.
2. **נשלחו כל שדות הטופס** — ובהם ששת כפתורי ה-submit של הדף. דפדפן
   שולח כפתור אחד בלבד, זה שנלחץ, ו-ASP.NET בוחר את המטפל לפי מה
   שהגיע. לכן רץ החיפוש במקום ההרחבה, הדף חזר זהה, והמסקנה הראשונה
   הייתה — בטעות — שהמנגנון חסום. `form_fields(page, submitter=...)`
   משמיט עכשיו את שאר הכפתורים.

ודבר שלישי, פחות טעות ויותר הפתעה: התשובה **אינה** מרנדרת את הפרטים
כ-HTML. הטבלאות `tblMoreInfo1_<n>` חוזרות ריקות, והשרת מזריק במקומן
קריאה ל-JavaScript עם XML:

```
f_buildMoreMsgInfo('<Msg MsgNumber="2046996" NotamID="C1760/26"
  FromDate="202608160800" ToDate="202608201000" ...>
  <MsgText>Q) LLLL/QAELC/IV/NBO/E /000/019/3059N03445E001</MsgText>...
```

`iaa.parse_more_info` קורא את ה-XML הזה, ומחזיר גוש נוטאם מלא שנכנס
ישירות ל-`parse_qline.parse_notam` — בלי שום הרכבה מחדש. כך שורת Q
מגיעה סוף סוף לפרסור, ואיתה זמני תוקף, גבהים, גיאומטריה ולוח זמנים.

**קצב ומטמון.** כל הרחבה עולה בקשה שלמה של ~1.4MB, ולכן:

* התוצאה נשמרת לפי מזהה נוטאם ב-`data/notam-details.json`. פרטי נוטאם
  אינם משתנים אחרי הפרסום, אז מספיק למשוך אותם פעם אחת.
* לכל היותר 15 הרחבות בריצה, עם 1.5 שניות ביניהן ותקציב זמן של 90
  שניות לשלב כולו.
* הודעה שאינה במטמון מוצגת בלי זמני תוקף, ותושלם בריצה הבאה.

הריסון אינו נימוס בלבד. ניסיון עם 25 הרחבות בריצה **תקע את ה-job ל-12
דקות**: השרת האט עד שהתשובות זלגו לאט יותר מה-timeout של השקע, ולכן
הוא מעולם לא נורה. `timeout` של שקע נמדד לכל `recv` בנפרד — ולכן
`_read_capped` קורא את הגוף בנתחים עם שעון קיר (25 שניות), וזה מה
שבאמת עוצר זחילה. בנוסף: תקציב זמן לשלב כולו, ו-`timeout-minutes` על
ה-job כרשת ביטחון. בפועל ריצה עם 15 הרחבות נמשכת כדקה.

מה שכן חסום ולא נגענו בו: `AeroInfo.asmx?WSDL` מחזיר
`Unauthorized Request Blocked` מ-Radware, ובקשת ASP.NET AJAX
אסינכרונית מחזירה `Error 100` של זיהוי בוטים. אין בהם צורך —
ה-postback הרגיל הוא הנתיב שהדפדפן עצמו הולך בו.

### מקורות אופציונליים עם הרשמה חינמית

אינם נדרשים — רשות שדות התעופה מספיקה. הם מוסיפים שורות Q וזמני תוקף:

**FAA NOTAM API** (מומלץ — רשמי ויציב)

1. הירשמו ב-<https://api.faa.gov/s/> וקבלו `client_id` ו-`client_secret`.
2. Settings → Secrets and variables → Actions → New repository secret:
   * `FAA_CLIENT_ID`
   * `FAA_CLIENT_SECRET`

**autorouter**

1. הירשמו ב-<https://www.autorouter.aero/> וקבלו אישורי OAuth2.
2. הוסיפו כסודות: `AUTOROUTER_CLIENT_ID`, `AUTOROUTER_CLIENT_SECRET`.

מספיק אחד מהשניים. אם שניהם מוגדרים — התוצאות מאוחדות, וכפילויות
מטופלות לפי מזהה הנוטאם.

**עד שיוגדר אישור, הדף מציג אזהרה שהנתונים אינם עדכניים** ואינו מתיימר
להראות "0 נוטאמים פעילים".

נמשכים ה-FIR `LLLL` וגם שדות התעופה `LLBG`, `LLHA`, `LLIB`, `LLRD`, `LLHZ` —
נוטאם ברמת שדה לפעמים כולל הגבלה מקומית שלא עולה לרמת ה-FIR.

**אין סינון תוכן.** כל מה שהמקור החזיר מוצג. הנפח קטן (סדר גודל של 12 פעילים),
ומגבלה חריגה בגובה נמוך היא בדיוק מה שמחפשים — מסנן עלול לבלוע אותה. מה שיש
זה סימון ויזואלי: נוטאם שרצפתו מתחת ל-3,000 רגל מסומן בצבע נפרד, ונוטאמים
מנהלתיים (`CHECKLIST`, `TRIGGER NOTAM`) מתויגים ויורדים לתחתית הרשימה — אך
נשארים גלויים.

### עמידות

אם כל המקורות נכשלים, `notams.json` הקיים **לא נדרס**. במקום זה:

* `stale` נקבע ל-`true`
* `last_error` מקבל את השגיאות
* `last_success` נשאר על הזמן האחרון שהצליח

הדף מציג את הנתונים הישנים עם אזהרה אדומה בולטת על גילם. נתון ישן עם חותמת
זמן כנה עדיף על דף ריק.

## פרסור שורת Q

הלב הטכני. שורת Q נראית כך:

```
Q) LLLL/QRTCA/IV/NBO/W/000/999/3155N03518E010
```

שמונה שדות מופרדים בלוכסן: FIR, קוד Q, תעבורה, מטרה, היקף, גובה תחתון,
גובה עליון, מיקום+רדיוס. שדה המיקום הוא `DDMM[NS]DDDMM[EW]RRR` — בדוגמה:
31°55'N, 035°18'E, רדיוס 10 מייל ימי.

מקרי קצה שמטופלים במפורש:

| מקרה | טיפול |
|------|--------|
| רדיוס `999` | כל ה-FIR. **לא** מצויר עיגול — מוצג כתג "חל על כל המרחב" ברשימה. |
| גבהים `000/999` | "ללא הגבלת גובה", לא 0 עד 99,900 רגל. |
| שורת Q חסרה או פגומה | הרשומה נשמרת עם `geo: null` ומופיעה ברשימה בלי סמן על המפה. |
| `PERM` בשדה סיום | תוקף קבוע, לא תאריך. |
| `EST` אחרי תאריך | מסומן כמשוער. |
| `NOTAMR` / `NOTAMC` | הנוטאם שהוחלף או בוטל מוסר, כך שלא יוצג פעמיים. |
| פריטי `F)`/`G)` | מדויקים יותר משורת Q וגוברים עליה בקביעת רצפת הגובה. |

הרצת הבדיקות:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py' -v
```

## שכבת מזג האוויר

`data/weather.json`, מאותו מקור בדיוק (`msgType=Weather`), עם מתג נפרד
בדף. השכבה כבויה כברירת מחדל — מי שנכנס לדף רוצה לדעת מה מוגבל, ומזג
האוויר הוא תוספת.

**רק AIRMET ו-SIGMET מצוירים על המפה.** ההבחנה חשובה:

* METAR ו-TAF מדווחים על **תחנה**, כלומר נקודה. מיקום התחנה אינו מופיע
  בשום מקום במקור — לא בדף, לא ב-`Locations.js`, ולא ב-16 קובצי הפמ"ת
  הפנים־ארצי (נסרקו; אפס קואורדינטות של שדות תעופה). לסמן אותם היה
  מחייב להמציא מיקומים, ולכן הם ברשימה בלבד.
* AIRMET ו-SIGMET נושאים את האזור **בטקסט עצמו**, כרשימת קודקודים:

  ```
  ... MT OBSC FCST WI N3321 E03548 - N3257 E03555 - N3018 E03435
      - N3042 E03426 - N3321 E03548 STNR INTSF=
  ```

`iaa.extract_area` מחלץ את הטבעת. הוא תומך גם בצורת השניות
(`N332130 E0354830`), עוצר ב-`STNR`/`MOV`/`NC`/`=` כדי שלא יבלע מספרים
שאינם קודקודים, ומחזיר `None` כשיש פחות משלוש נקודות — שתי נקודות אינן
פוליגון.

## שכבת הפמ"ת

**זהו הנתון החשוב יותר מבין השניים.** הוא מדויק, יציב ובשליטה מלאה — שכבת
הנוטאמים היא תוספת מעליו.

מקור: `https://www.gov.il/BlobFolder/guide/aip/he/aip_א'-17.pdf`
נספח ב' (אסור/מוגבל/מסוכן) ונספח ג' (אסור לכטב"ם — הרלוונטי ביותר לרחפנים).

### כיסוי כלל־ארצי

במקור החילוץ הוגבל לתיבת מטה בנימין, כדי שהמפה תישאר קריאה. בפועל זה
יצר בעיה הפוכה: אזור כמו `LLR83` נמתח על 50 ק"מ בצפון השומרון ונוגע
בתיבה ברצועה של 2 ק"מ בלבד — ואז הוא משתלט על התצוגה בלי סיבה.

הכיסוי הורחב לכל הארץ (**29.0–33.5°N, 33.5–36.5°E**), וכל אזור מוצג
בהקשר האמיתי שלו. הכלי התחיל כמפה של מטה בנימין, וכשהוא הפך לארצי
ירדה גם תווית האזור: נשאר כפתור אחד, "כל הארץ", לחזרה לתצוגה המלאה
אחרי שמתקרבים למקום מסוים.

### gov.il חוסם הורדה אוטומטית

נבדק מול הרשת האמיתית מ-GitHub Actions: הקישור הישיר מחזיר **404** בשתי
צורות הקידוד, ודפי המדריך מחזירים **403**. הכתובת תקפה בדפדפן — האתר
חוסם לקוחות שאינם דפדפן ו/או כתובות IP של מרכזי נתונים.

לכן ה-PDF מגיע ידנית. זה עולה בקנה אחד עם המפרט, שהגדיר את שכבת הפמ"ת
כעבודה חד־פעמית וידנית ברובה. הסקריפט מוצא אותו לבד באחד משלושה מקומות,
לפי הסדר:

1. `--pdf <נתיב>`
2. ארכיון `*.zip` בשורש המאגר שמכיל את `א'-17.pdf`
3. `data/aip-a17.pdf`

### הטבלה נקראת כטבלה, לא כטקסט

זה החלק שהכי קל לטעות בו, ולכן הוא מתועד כאן.

pdfplumber מחלץ מהמסמך טקסט דו־כיווני: **העברית יוצאת הפוכה והספרות
יוצאות תקינות.** במקרה שלנו זה דווקא נוח — הנתון הקריטי לבטיחות,
הקואורדינטות, אינו עובר שום טרנספורמציה. רק השם צריך היפוך.

הניסיון הראשון קיבץ קואורדינטות לפי טקסט שטוח, בהנחה שטבעת נסגרת כשהנקודה
האחרונה חוזרת לראשונה. זה נתן פוליגונים שנראו תקינים אך נמתחו על 180 ק"מ
— מטווח בגודל חצי מדינה. `page.extract_tables()` מחזיר עמודות אמיתיות,
ואז הכלל חד־משמעי ולא היוריסטי: **אזור חדש מתחיל בשורה שבה עמודת "קוד
זיהוי" מלאה, ונמשך עד המזהה הבא.**

יש גם בדיקת שפיות בסוף: אזור שנמתח על יותר ממעלה אחת (כ-110 ק"מ) מדווח
כחשוד במקום להיבלע בשקט.

### מה לא נכנס לשכבה

הסקריפט שמרני בכוונה. **אזור מגבלה שגוי מסוכן יותר מאזור חסר**, ולכן
כל אחד מהמקרים הבאים מדווח ומדולג ולא מנוחש:

* אזור שקואורדינטותיו מפורסמות במקום אחר במסמך ואינן בטבלה
* הגדרת עיגול בלי רדיוס מספרי
* נקודה בודדת בלי רדיוס

גבולות שמתוארים במסמך כקשת ("מהנקודה הקודמת בקשת לאורך גבול LLP13")
מקורבים בקו ישר בין הנקודות המפורסמות. זו הערכה, לא העתקה מדויקת.

#### שמורות טבע וגנים לאומיים — הפער מול האפליקציה של רת"א

מי שמשווה את המפה הזאת לאפליקציית הכטב"מים של רת"א רואה שם הרבה יותר
פוליגונים, והם נראים אחרת — עוקבים אחרי קווי שטח ולא אחרי מצולעים.

הסיבה אינה שהם נשכחו. **נספח ה' לפרק א-17 מונה 542 אזורים כאלה — שמורות
טבע, גנים לאומיים ואתרי קינון — בשמם בלבד.** 549 שורות טבלה, **אפס
קואורדינטות**. הפמ"ת עצמו מפנה לשכבות גיאוגרפיות נפרדות של רט"ג ורת"א:

* `https://www.parks.org.il/new/tisa/`
* `https://www.gov.il/he/Departments/Guides/aip?chapterIndex=11`

בדיקה של הדף הראשון החזירה 200 עם 0 קישורי שכבה ישירים. לצייר את
האזורים בלי מקור נתונים אמיתי היה אומר להמציא גבולות, ולכן הם אינם
במפה — והדף אומר את זה במפורש מתחת למקרא.

### הרצה

Actions → **בניית שכבת הפמ"ת**:

* `mode: dump` — מדפיס את טקסט ה-PDF ליומן, לאיתור עמודי הנספחים
* `mode: build` — מחלץ, ממיר ל-GeoJSON ועושה קומיט

מקומית:

```bash
pip install -r requirements.txt
python3 scripts/build_aip_geojson.py
python3 -m unittest discover -s scripts -p 'test_*.py'
```

## הרצה מקומית

```bash
python3 -m http.server 8000
# ואז http://localhost:8000
```

הדף קורא את הקבצים מ-`data/` ביחס לשורש, אז צריך שרת — פתיחת `index.html`
ישירות מהדיסק לא תעבוד בגלל מדיניות `file://`.

משיכה ידנית של נוטאמים:

```bash
python3 scripts/fetch_notams.py              # משיכה וכתיבה
python3 scripts/fetch_notams.py --dry-run    # בלי לכתוב
python3 scripts/fetch_notams.py --input raw.txt  # פרסור קובץ מקומי, לדיבוג
```

## מגבלות תפעוליות שחשוב להכיר

* **ה-repo חייב להיות ציבורי.** ב-repo ציבורי דקות Actions הן חינם ובלתי
  מוגבלות. ב-repo פרטי המכסה היא 2,000 דקות בחודש **לכל החשבון** — הרצה שעתית
  תשרוף אותה ותפגע בפרויקטים אחרים.

* **cron מושבת אחרי 60 יום ללא פעילות.** ב-repo ציבורי חינמי GitHub משבית
  אוטומטית תזמוני cron אם לא הייתה פעילות ב-repo במשך 60 יום. הקומיטים
  השעתיים של הסקריפט עצמם נחשבים פעילות, כך שבפועל זה לא אמור לקרות — אבל
  אם המשיכה תיכשל לאורך זמן ולא ייווצרו קומיטים, התזמון ייעצר בשקט. שווה
  לבדוק את חותמת הזמן בראש האתר מדי פעם.

* **עיכוב של עד שעה** בין פרסום נוטאם להופעתו באתר. זה מובנה בארכיטקטורה.

* **הפמ"ת מתעדכן במחזורי AIRAC** (כל 28 יום). שכבת המגבלות הקבועות לא
  מתעדכנת לבד — צריך להריץ מחדש את `build-aip.yml` אחרי עדכון.
